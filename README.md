# Reel Picks — AI Movie Recommendation Engine

A full-stack app that takes a user's movie preferences (genres, mood, era,
favorites, language, things to avoid) and returns **live, personalized
recommendations** generated by Google Gemini — no static/local movie database.

- **Backend:** Python + FastAPI, calls the Gemini API on each request
- **Frontend:** Single-page HTML/CSS/JS (cinema-ticket themed UI)
- **Model:** `gemini-3.1-flash-lite` by default (free tier); `gemini-3-flash-preview`
  also supported — just change one env var. (Older names like
  `gemini-2.5-flash-lite` and `gemini-1.5-pro` are retired for new API keys.)

The project layout follows Vercel's zero-config conventions for FastAPI, so
it runs locally with plain `uvicorn` **and** deploys to Vercel with no
extra glue code.

---

## 1. Get a free Gemini API key

1. Go to **https://aistudio.google.com/apikey**
2. Sign in with a Google account and click **Create API key**
3. Copy the key — this is free to use within Gemini's free-tier rate limits

## 2. Project structure

```
movie-recommender/
├── api/
│   └── main.py            # FastAPI app + Gemini integration (Vercel entrypoint)
├── public/
│   └── index.html         # UI, calls /api/recommend on the same origin
├── requirements.txt        # Used for both local dev and Vercel's build

└── README.md
```

`api/main.py` is a recognized Vercel entrypoint name, and `public/` is
Vercel's convention for static assets served straight from its CDN — that's
the whole reason for this layout.

## 3. Run it locally

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env
# then open .env and paste your key:
#   GEMINI_API_KEY=your_actual_key_here
#   GEMINI_MODEL=gemini-3.1-flash-lite

uvicorn api.main:app --reload --port 8000
```

The API is now running at `http://localhost:8000`.

- Interactive docs: `http://localhost:8000/docs`
- Health check: `GET http://localhost:8000/api/health`

For the frontend, open a second terminal:

```bash
cd public
python -m http.server 5500
```

Open `http://localhost:5500`. The page auto-detects this and points its
requests at `http://localhost:8000`; when deployed, it calls the API on the
same origin instead — no config needed either way.

### API contract

`POST /api/recommend`

```json
{
  "genres": ["Sci-Fi", "Thriller"],
  "mood": "thought-provoking",
  "favorite_movies": "Inception, Arrival",
  "era": "recent releases (last 3 years)",
  "language": "no preference",
  "avoid": "gore",
  "count": 6
}
```

Response:

```json
{
  "model_used": "gemini-3.1-flash-lite",
  "recommendations": [
    {
      "title": "...",
      "year": "...",
      "genre": "...",
      "reason": "...",
      "rating_hint": "..."
    }
  ]
}
```

Every call hits the Gemini API fresh — nothing is cached or hardcoded, so
results genuinely vary run to run.

## 4. Deploy to Vercel

### Option A — Git integration (recommended)

1. Push this project to a GitHub/GitLab/Bitbucket repo (make sure `.env` is
   **not** committed — `.gitignore` already excludes it).
2. Go to **https://vercel.com/new** and import the repo.
3. Leave the framework preset on its default ("Other" is fine — no build
   command is needed, Vercel detects `api/main.py` automatically).
4. Before the first deploy (or right after, then redeploy), go to
   **Project Settings → Environment Variables** and add:
   - `GEMINI_API_KEY` = your key
   - `GEMINI_MODEL` = `gemini-3.1-flash-lite`
5. Click **Deploy**.

Vercel does **not** read `.env` files — it only uses variables set in the
dashboard (or via `vercel env add`, see below).

### Option B — Vercel CLI

```bash
npm install -g vercel
vercel login

cd movie-recommender
vercel                       # first deploy -> creates a preview URL
vercel env add GEMINI_API_KEY
vercel env add GEMINI_MODEL
vercel --prod                 # promote to your production URL
```

`vercel env add` prompts you to paste the value and choose which
environments (Production/Preview/Development) it applies to.

### How it behaves once deployed

- `public/index.html` is served directly from Vercel's CDN at `/`.
- Everything else (`/api/recommend`, `/api/health`, `/docs`) runs as a
  single Vercel Function built from `api/main.py`.
- `vercel.json` sets `maxDuration: 30` for that function, since a Gemini
  call plus JSON parsing occasionally takes a few seconds — comfortably
  under Vercel's Hobby-plan limits.
- Because the frontend and API share one domain in production, the
  `API_BASE` in `public/index.html` resolves to the same origin
  automatically — no URLs to edit after deploying.

### After deploying

- Visit your Vercel URL — the UI should load instantly from the CDN.
- Submit the form; the first request may be slightly slower (cold start),
  after which Vercel's Fluid compute keeps the function warm under traffic.
- If you see a 500 with "GEMINI_API_KEY is not set", double-check the
  environment variable was added *and* redeploy — env var changes require a
  redeploy to take effect on existing deployments.

## 5. Notes on the free tier

- `gemini-3.1-flash-lite` — fastest and cheapest, generous free-tier quota,
  great default for this use case
- `gemini-3-flash-preview` — stronger reasoning, still on the free tier
- If you hit a `404 ... no longer available to new users` error, the model
  name has been retired for new API keys — switch `GEMINI_MODEL` to one of
  the two above (in `.env` locally, or in Vercel's Environment Variables).
  Google periodically retires older generations (e.g.
  `gemini-2.5-flash-lite`, `gemini-1.5-pro`) even while older projects may
  still see them listed, so check
  [ai.google.dev/gemini-api/docs/pricing](https://ai.google.dev/gemini-api/docs/pricing)
  if this happens again.
- If you hit a `502` error with a quota/rate-limit message, wait a minute or
  switch `GEMINI_MODEL`.

## 6. Extending this to other recommendation types

The prompt-building logic in `build_prompt()` (`api/main.py`) is the only
place that's movie-specific. To reuse this same architecture for books or
career paths, swap that function's wording and the `MovieRecommendation`
schema for a `BookRecommendation` / `CareerRecommendation` model — the
FastAPI route, Gemini call, and JSON-parsing logic stay the same.
